# LitAnchor v0.6 frozen holdout rubric

This rubric is frozen before the three holdout papers are processed. Holdout
papers provide only Zotero metadata and their original PDFs. Reference notes,
prefilled Evidence/Claim ledgers and paper-specific Skill rules are prohibited.

## Required run contract

- Start from empty `evidence.json` and `claims.json`.
- Use PyMuPDF physical pages as the authoritative source for evidence, page
  links, bounding boxes and crops.
- MinerU may add aligned structure hints only; it must not create authoritative
  EvidenceUnits.
- Generate the canonical Final-template note without editing intermediate JSON.
- Run independent fidelity and recall reviews.
- Preserve all warnings and blockers.

## Passing gates

- Final-template structural completeness: 100%.
- Core factual claims with traceable evidence: 100%.
- Severe unsupported claims: 0.
- Physical PDF-page accuracy: at least 99%.
- Core numeric fidelity: at least 99.5%, with zero core-result numeric errors.
- Required method, experiment, result and limitation groups: present or
  explicitly verified as not applicable.
- Key visual crops: complete and traceable to original PDF pages.
- MinerU failure: safe PyMuPDF fallback with no loss of evidence authority.
- Private data leakage or overwrite of an existing note: 0.

## Holdout integrity

If a holdout result motivates any change to the distributable Skill, prompts,
schemas, templates or quality rules, that paper becomes a development case. It
must be replaced by a newly frozen paper before the release decision.
